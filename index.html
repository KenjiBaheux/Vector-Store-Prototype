Semantic Embedder API enables the generation of text embeddings on-device. This allows for privacy-preserving semantic understanding, low-latency applications, and avoids server-side costs. The API is currently supported only on desktops (Linux, Mac and Windows).

To begin testing, ensure you are using the latest version of Chrome Canary ie, it should be greater than 153.0.7979.0. You must manually enable the following experimental flag to access the Semantic Embedder API:

chrome://flags/#semantic-embedder-api → Enabled

After enabling the flag and relaunching Chrome Canary, reload this page to test the on-device Vector Store API.

Vector Store API Prototype Architecture

Specification Compliance & Experimental Integration

1. End-to-End Built-in AI Pattern

Our polyfill adheres strictly to the common pattern established by Built-in AI APIs: availability() -> create() / retrieve() -> execute -> close(). 

// 1. Check API availability
if (!VectorStore || (await VectorStore.availability()) === "unavailable") {
  console.error("Vector Store API is not available.");
}

// 2. Create store with chunking strategy & distance metric
const vectorStore = await VectorStore.create({
  id: "my-app-notes",
  chunkingStrategy: { maxChunkSizeTokens: 400, chunkOverlapTokens: 50 },
  distance_type: 'Cosine'
});

2. Experimental Semantic Embedder (EmbeddingGemma-300m)

Under the hood, the polyfill detects window.SemanticEmbedder when available, and leverages on-device embeddings. It also applies the appropriate taskType optimization parameter for each operation:

  • taskType: "retrieval-document" — Applied automatically during vectorStore.insert() and updateContent() so document chunks are optimized for indexing.
  • taskType: "retrieval-query" — Applied automatically during vectorStore.findNearest() so search queries are optimized for retrieval against documents.

3. Persistent Indexing in IndexedDB

All stores, original items, and embedding vectors (Float32Array) are stored inside an IndexedDB database named VectorStorePrototypeDB. This allows developers to call VectorStore.list() to enumerate databases across browser sessions and call VectorStore.retrieve(id) to open a store without re-ingesting documents.
